M365 Copilot — Opus, flat-rate → GitHub Copilot Business — Opus agent, metered
Arbitraging two billing surfaces over one model family — think free at the front, bill at the back.

TIER 1 · ALL PHASES
Every phase is flat-rate. Discovery, reasoning, pre-flight, prompt synthesis — none of it is metered. Explore unboundedly: read 50 files, chase three dead-end designs, ask 20 clarifying questions. The bill doesn't move.
PRO TIP · BASE64 UPLOAD
Bypass the Python stream-reader. When source has backticks, $variables, or nested quotes that mangle file parsing, base64-encode the file as .txt and upload that. Copilot decodes it cleanly — no escape corruption, no truncation.
HANDOFF · BLUEPRINT
Not a one-liner — a full work order. The markdown prompt averages 200+ lines, often 500–1,000 for multi-file refactors. Bakes in whitelist/blacklist, design choices, acceptance criteria, non-goals, and thinking-effort dial. Longer blueprint = narrower agent reasoning surface = fewer wandering credits.
TIER 2 · ALL PHASES
Every token costs premium credits. Execution and verification are both billed — every thought, every grep, every clarifying question burns credits. Keep Tier 2 on rails: mechanical execution of a pre-validated plan, nothing more. Exploration here is the most expensive failure mode in the entire workflow.

💰 The Economic Argument (the whole point)

The core insight: Claude Opus is the same underlying model in both tiers, but the billing surface is radically different. M365 Copilot Chat is an unmetered conversational front-end to the same reasoning capability that GitHub Copilot meters by the token. So you move every byte of reasoning that can happen before the agent touches the repo into Tier 1.

You are effectively arbitraging two cost models for one model family.

🧠 What Tier 1 Is Really Doing

Think of Tier 1 as a senior engineer doing the design review and writing the work order, and Tier 2 as the contractor who shows up to build exactly what's on the work order. The contractor is expensive per hour, so you don't pay them to figure out what to build — you pay them to build it.

Concretely, Tier 1 absorbs:

  • The search cost — pulling in docs, source, prior decisions, framework references.
  • The wrong-turn cost — exploring two or three approaches and discarding the bad ones happens in chat, not in the agent.
  • The clarification cost — every "wait, did you mean X or Y?" round-trip is free here and ruinous there.
  • The verification-of-assumptions cost — confirming a function exists, a parameter is real, a file path is correct, before the agent ever spins up.

⏱️ The Honest Tradeoff: Time

This is not a free lunch — you're paying in wall-clock time instead of credits:

  • Tier 1 round-trips are slow. A real design conversation might span 5–20 turns of chat, file uploads, and back-and-forth. That's minutes to an hour of human-in-the-loop time.
  • You are the bottleneck. Tier 2 can rip through a 10-file refactor unattended; Tier 1 needs you to read, react, and steer.
  • Context-switching tax. Moving from "thinking partner" mode in chat to "review the agent's diff" mode in the IDE has its own cognitive cost.
  • Diminishing returns on small tasks. For a one-line typo fix, the Tier 1 pre-flight is overhead. The two-tier model pays off as task complexity rises.
So the tradeoff is: you spend more of your own time in exchange for spending fewer credits and getting a higher first-pass success rate from the agent. For mechanical fixes, skip Tier 1. For anything architectural or anything you'd hate to see the agent flail through, Tier 1 is the cheap insurance policy.

📌 When This Workflow Wins vs. Loses

✅ Wins big when

  • Multi-file refactors across an unfamiliar or large codebase
  • Anything touching external APIs / cmdlets / SDKs where parameter audits matter
  • Greenfield design where the agent could plausibly pick the wrong pattern
  • Work where a wrong turn costs more credits than a careful plan costs time

⚠️ Loses (or breaks even) when

  • Single-file, well-scoped, mechanical edits
  • Tasks where you already have the design fully in your head
  • Time-critical fixes where wall-clock matters more than credit spend
